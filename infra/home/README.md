# Sportfond: домашнее размещение

**Актуальная инструкция:** [постоянный туннель](NAMED-TUNNEL.md). Для текущего запуска нужны оба файла: `compose.yaml` и `compose.named.yaml`. Команды ниже описывают первоначальный тест Quick Tunnel; его временная ссылка больше не используется.

Это отдельный тест связи, а не восстановленный backend. Он возвращает только публичный JSON на / и /health. Нет доступа к файлам сервера, базе, ключам или панелям управления.

## Запуск на Ubuntu / WSL2 с Docker Compose

```sh
docker compose config --quiet
docker compose up -d
curl --fail http://127.0.0.1:18765/health
docker compose logs --tail=50 tunnel
```

В логе tunnel появится временный HTTPS-адрес *.trycloudflare.com. Откройте /health по этому адресу с другого подключения, например с телефона через мобильную сеть. Локальный порт опубликован только на 127.0.0.1; интернет-трафик поступает через исходящий туннель.

## Остановка

```sh
docker compose down
```

Команда действует только на compose-проект sportfond-home-probe. Соседние контейнеры не затрагиваются. Данных и volumes у пробы нет.

## Ограничения

- Quick Tunnel меняет адрес после пересоздания и не имеет гарантии доступности. Не вписывайте его в production frontend.
- Для постоянного API потребуется именованный туннель с постоянным HTTPS-адресом, отдельной безопасной передачей токена и проверкой DNS. Текущие DNS и почта не меняются.
- restart: unless-stopped перезапускает контейнеры при работающем Docker; он не гарантирует запуск Windows, WSL2 или Docker после перезагрузки и не отключает сон.
- Используются официальные образы. После проверки запишите их фактические digest для воспроизводимого развёртывания; не обновляйте production через latest без проверки.
- Внешнюю доступность нужно проверить отдельно от работоспособности локального API.
- Рабочие боты, email и распознавание будут отдельными службами. Для них нужны исходники, секреты и backup базы.
- Для домашней базы и файлов нужен отдельный зашифрованный backup вне этого компьютера; GitHub хранит код и инструкции.
